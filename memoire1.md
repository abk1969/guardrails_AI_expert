## 5. Faits techniques à NE PAS oublier

### AI Act Art. 99 — tiers d'amendes (ne pas confondre)

| Tier | Infractions concernées | Plafond |
|---|---|---|
| Art. 99(3) | **Art. 5 uniquement** (pratiques prohibées) | **35 M€ / 7 %** |
| Art. 99(4) | Art. 16, 22, 23, 24, 25, 26, 27, 49, 50, etc. | **15 M€ / 3 %** |
| Art. 99(5) | Fausse information aux autorités | **7.5 M€ / 1 %** |

⚠️ Erreur historique corrigée sur SIA-001 : l'Art. 49 relève de Art. 99(**4**) = 15 M€/3 %, **pas** 35 M€/7 %.

### Structure TS acceptée pour `riskScenarios[].mappings`

Uniquement ces 4 clés (sinon erreur TS) :
```ts
{ owaspLlm?: string; owaspAgentic?: string; mitreAtlas?: string; nistRmf?: string; }
```

Le legacy `aiPolicyContentLegacyV2.ts` utilise d'autres clés (`owaspLlm2`, `mitreAtlas2`, `cwe`, `iso27001`…) → neutralisé par `// @ts-nocheck`. **Ne pas ajouter ces clés au v3.**

### Structure TS acceptée pour `riskScenarios[].impact`

Uniquement ces 7 clés :
```ts
{ confidentiality?: string; integrity?: string; availability?: string;
  strategic?: string; financial?: string; reputational?: string; operational?: string; }
```

Éviter les clés hors schema (`legal`, `individual`, etc.) — les fusionner dans `operational` ou `reputational` selon le sens.

### Pipeline d'enrichissement

```
pssi-ia-v3.json (extraction PDF)
         +
pssi-ia-v3-enrichments.json (contenu validé user)
         ↓
scripts/generate-pssi-v3-artifacts.cjs

backend/.../mcp/static-data/pssi-ia-v3.json  ← MCP backend (outils search_pssi_sia etc.)
```
